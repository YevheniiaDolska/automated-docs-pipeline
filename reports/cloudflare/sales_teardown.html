Public docs teardown: highest-impact fixes and the automation layer to prioritize first

Cloudflare's developer documentation spans 7,869 crawled pages with strong retrieval readiness (94.5 overall score, 90% chunkability). However, 43 confirmed broken internal links disrupt navigation, API reference coverage sits at only 56.92% across 2,975 detected API pages, and example reliability is critically low at 46.15%. Evidence backing for key claims reaches 61.93% (2,435 of 3,932 claims), while 10 links remain unverified due to authentication or rate-limiting. Overall confidence stands at 83.95%, with crawl coverage at 100% of the 7,955 in-scope pages.

What I’d Prioritize First

  • Fix all 43 confirmed broken internal linkshigh value · high impact · low

    Immediate trust and SEO win with minimal engineering effort, directly reducing user frustration and support tickets for navigation failures.

  • Implement automated testing and refresh cycle for code examples to lift reliability from 46.15% toward 80%+high value · critical impact · high

    Code examples are the highest-leverage onboarding asset; fixing reliability directly shortens time-to-first-success and reduces developer churn.

  • Close API reference coverage gap from 56.92% to 85%+ by auditing 2,975 detected API pages and generating missing usage docshigh value · critical impact · high

    Incomplete API docs drive support volume and integration abandonment; closing the gap unlocks self-service adoption and enterprise deal velocity.

Automation Layer To Add First

  • Deploy CI-integrated link checker to catch the 43 broken internal links (and future regressions) pre-publish, preventing trust erosion and SEO penalties with zero ongoing manual effort.
  • Establish nightly automated test harness for code examples across all 7,869 pages to lift the 46.15% reliability estimate above 80%, directly reducing developer onboarding friction and support load from broken samples.
  • Build API reference coverage monitor tied to OpenAPI specs to track the 2,975 detected API pages and alert when coverage drops below 85%, ensuring new endpoints ship with usage docs and preventing the current 56.92% gap from widening.

What Looks Strong

  • Excellent retrieval readiness (94.5 score) with 90% chunkability and 100% answerability, optimizing AI-assisted search and support deflection
  • Comprehensive crawl coverage at 100% of in-scope pages (7,869 of 7,955), ensuring audit completeness
  • Strong freshness metadata coverage at 93.46%, enabling users and systems to assess content currency

Main Risks

  • 43 confirmed broken internal links create friction in user journeys, erode trust, and degrade SEO authority
  • API reference coverage at 56.92% leaves nearly half of API surfaces undocumented or poorly linked, increasing support burden and integration failure risk
  • Example reliability at 46.15% means over half of code samples may be outdated, broken, or untested, directly impacting developer time-to-value and product perception
  • 61.93% evidence coverage for claims suggests ~1,500 assertions lack supporting links, code, or data, weakening credibility and onboarding confidence
